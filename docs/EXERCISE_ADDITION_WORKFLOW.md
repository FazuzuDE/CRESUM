# Добавление упражнения или тренажёра в CRESUM

## Как начать

Достаточно названия, например «Добавь вертикальный велотренажёр».
Агент сам находит исходные материалы, проверяет каталог, готовит иллюстрации,
вносит согласованные изменения, запускает проверки и открывает PR.
Промежуточные шаги не требуют согласования. Новые иллюстрации показать
владельцу одним комплектом перед подключением в приложение, если владелец
явно не разрешил автоматическую приёмку. После утверждения продолжить работу
без повторного запроса. Уточнять название только когда варианты существенно
различаются, а контекст проекта и проверенные источники не позволяют выбрать.

## 1. Проверить каталог и определить вариант

1. Сверить актуальный `develop`, открытые PR, локальные изменения и правила в
   [AGENTS.md](../AGENTS.md). Проверить упражнения, оборудование, вложения,
   синонимы, стартовые программы, инструкции и реестр иллюстраций.
2. Определить, нужен ли новый элемент каталога, вариант существующего
   упражнения, карточка оборудования или только иллюстрация. Переиспользовать
   существующий ID и компонент, когда смысл совпадает. Новый устойчивый ID
   нужен при значимом отличии оборудования, хвата, опоры или траектории.
   У старых ID, сохранённых тренировок и статистики сохраняется исходный смысл.
3. Если название относится к тренажёру, определить, какое движение им
   иллюстрируется. Изображение самого оборудования и карточку движения
   готовить по соответствующим стандартам. Сверить точную конфигурацию с
   руководством производителя или профильным источником. Зафиксировать ссылку,
   дату, технику и границы применимости. Тексты и изображения CRESUM готовить
   самостоятельно.
4. Выбрать фактический способ учёта в существующей модели. Для силовых
   использовать повторения и вес, где он применим, для удержаний — время,
   для кардио — поддерживаемый показатель по задаче. Указать работу на каждую
   сторону, если применимо. При добавлении записи заполнить таксономию, перевод,
   натуральные поисковые синонимы и инструкцию на всех языках текущего реестра.
   Мышечные роли задавать для точного варианта по проверенным данным. Красную
   заливку выводить через существующую карту. Для чисто рекомендательного
   блока отдельно проверить, предусмотрена ли запись результата в журнал.

Подробнее об идентификаторах, поиске и учёте в
[EXERCISE_LIBRARY.md](EXERCISE_LIBRARY.md).

## 2. Подготовить изображения

1. Взять утверждённые эталоны персонажей и оборудования из
   [реестра ассетов](handoff/ASSET_INDEX.md). Проверить доступность самих файлов.
   Если оригинальный эталон недоступен, можно подготовить предварительный
   вариант по близким действующим иллюстрациям CRESUM и явно обозначить
   замену при показе. Интеграция такого варианта требует принятия владельцем.
2. Для упражнения подготовить мужскую и женскую пары START/FINISH. Оборудование,
   ракурс, масштаб, стиль, одежда и освещение одинаковы между фазами. Для
   циклического движения показать два различимых момента цикла. Изолированная
   миниатюра тренажёра или крепления повторяет контракт своей категории.
3. Проверить механику точного варианта, контакты рук и стоп, положение суставов,
   геометрию тренажёра, видимость персонажа и оборудования, лицо, оттенки кожи,
   ткани и материалы. Сравнить исходник в полном размере и изображение в
   целевом масштабе на экране. Показать обе модели одним комплектом на приёмку.
   Для логотипов хранить чистую базу и сделать предпросмотр с наложением.
4. Сохранить оригинал, точный промпт, фактически использованные референсы,
   хеши, ревизию, размеры, параметры экспорта и статус QA. В репозиторий
   добавить выбранные WebP и метаданные. Архив исходников вести по
   [VISUAL_STORAGE.md](VISUAL_STORAGE.md).

## 3. Сохранить размеры и качество

Размер контейнера на экране и разрешение файла проверяются отдельно.
Перед экспортом сверить размеры в актуальном компоненте и профиль ассета
в [EXERCISE_ASSETS.md](EXERCISE_ASSETS.md). Новая карточка в существующем
списке наследует его размер, скругление и `contain`. Существующие размеры,
кадрирование и качество ассетов не менять без отдельного указания владельца.

| Поверхность или ассет                                 | Размер и правило                                                                                                    |
| ----------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| Стандартная строка в обзоре готовой программы         | 52 × 52 логические единицы                                                                                          |
| Миниатюра ходьбы на дорожке                           | 64 × 64 логические единицы, размер уже согласован для этой карточки                                                 |
| Миниатюры в библиотеке упражнений и заголовке техники | 76 × 76 логических единиц                                                                                           |
| Пара кадров по стандарту дорожки                      | Исходный диптих 1774 × 887. Два точных кадра по 887 × 887 пикселей. WebP quality 92, effort 6.                      |
| Изолированная миниатюра оборудования или рукояти      | Профиль конкретного компонента и утверждённого ассета. Некоторые текущие рукояти используют прозрачный WebP 512 px. |

Кадры на 887 × 887 вырезать из исходного диптиха без пересчёта пикселей,
растягивания, заполнения полями и обрезки конечностей или оборудования.
Экспортировать из оригинала одним проходом. Если исходник не подходит под
контракт, исправить кандидат до приёмки. Существующие профили оборудования
могут отличаться от профиля кадров техники.

## 4. Подключить, проверить и отправить

1. Привязать изображения к точным ID, версии, фазе и персонажу через
   существующий механизм. Для отсутствующей иллюстрации использовать штатную
   заглушку. Проверить целевые экраны, смену персонажа, светлую и тёмную темы,
   узкий экран, доступность и работу без сети.
2. Для брендируемого тренажёра использовать оригинальный вектор CRESUM
   отдельным слоем. Хранить относительные границы размещения для конкретной
   ревизии кадра. Основной знак и пустая по умолчанию соседняя позиция спонсора
   независимы. Реализацию админ-публикации отмечать только после её подключения
   и проверки. См. [спецификацию брендирования](superpowers/specs/2026-11-08-branding-admin-design.md).
3. Проверить каталог, поиск, фильтры и добавление в тренировку, если добавлен
   элемент каталога. Для упражнения с записью результата проверить сохранение
   в истории и прогрессе. Для рекомендательного блока проверить видимость и
   корректные единицы на целевых экранах. Прогнать проверку размеров файлов,
   typecheck, lint, локализацию, релевантные тесты и сборку, если меняется
   доставка ассетов. Проверку на устройстве отмечать отдельно.
4. Опубликовать рабочую ветку и создать PR в `develop`. Получить реальный номер
   PR, применить `npm run version:pr -- <номер>`, проверить версию и статус CI.
   В отчёте указать, что именно подключено, какие проверки пройдены и что
   осталось проверить. См. [PR_VERSIONING.md](PR_VERSIONING.md).

## Пример из PR №317

«Ходьба на беговой дорожке» уже существовала как кардиоблок двух готовых
программ. Сначала подготовили и утвердили женскую и мужскую пары, затем
подключили первый кадр каждой пары в карточке 64 × 64. Оба кадра каждого
персонажа сохранены в размере 887 × 887. Логотип выводится отдельным слоем.
PR добавляет иллюстрации для существующих кардиоблоков. Самостоятельная запись
в каталоге, запись длительности в журнал и управление знаками из рабочей
админ-панели остаются отдельными задачами.
