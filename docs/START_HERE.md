# CRESUM — начать здесь / resume here

Это стабильная точка входа для нового чата, аккаунта или среды разработки.
Рабочая ветка мобильного приложения — **develop**. Всегда заново получить её
HEAD и статусы PR: датированные снимки ниже не являются живым dashboard.

## Первые действия

1. Проверить repository, branch, `git status`, локальные изменения и remote HEAD.
2. Прочитать корневой AGENTS.md, PRODUCT, DESIGN_SYSTEM, ROADMAP и DECISIONS в docs.
3. Прочитать [снимок контекста от 2026-11-17](handoff/2026-11-17-context-ru.md)
   и [проверенное состояние](handoff/2026-11-17-state.json), затем перепроверить
   изменившиеся PR/локали. Поиск #285 уже merged; #286/#287 при снимке ещё open.
4. Найти owning documents задачи через [полный индекс](handoff/DOCUMENT_INDEX.md).
   Для визуальных задач открыть [реестры ассетов](handoff/ASSET_INDEX.md), а не
   восстанавливать изображение по памяти или имени внешнего файла.
5. Кратко сверить с владельцем/задачей точку продолжения. Не повторять уже
   реализованные функции и не объявлять исторический draft текущим приоритетом.

## Новое упражнение или тренажёр

Если пользователь дал название, начать с [порядка добавления](EXERCISE_ADDITION_WORKFLOW.md).
Там зафиксированы размеры карточек, параметры кадров, приёмка изображений и PR.

## Что сохранять неизменно

- Offline Core, стабильные ID/исторические снимки, восстановление тренировок.
- Утверждённый светлый стиль, shared components, точные варианты оборудования.
- Все новые app-controlled тексты и поисковые альтернативы на всех текущих
  языках реестра, включая ещё не прошедшие физическую release-проверку локали.
- PR workflow, проверенная версия по фактическому номеру PR; merge за владельцем.
- Разделение Mobile и отдельно разрешённого приватного визуального workstream.

Owning documents и новые прямые решения владельца важнее старого снимка. Решения
из чата синхронизировать в owning documents и DECISIONS в том же PR; отмечать
статус approved / implementation pending / merged / deployed / accepted честно.
Не хранить только в памяти чата. При новой передаче добавлять датированный снимок
и обновлять эту точку входа; старые снимки сохранять как историю.

## Сообщение для нового ассистента

> Продолжаем CRESUM. Начни с docs/START_HERE.md и AGENTS.md актуальной develop
> FazuzuDE/CRESUM. Сверь текущие HEAD, PR, языки и проверки. Прочитай документы
> моей текущей задачи, сообщи точку продолжения и продолжай согласованную работу.
> Не начинай проект заново и не теряй утверждённые решения из датированного handoff.

Подключение нового аккаунта само по себе не доказывает наличие старых чатов,
изображений, GitHub/серверных доступов. Отсутствующие источники перечислять явно.
Этот PR не публикует приватные master-изображения, переписки и credentials.
