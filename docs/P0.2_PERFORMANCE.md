# P0.2 interaction performance

## Findings and changes

- Opening the Exercise Library mounted all 71 visible rows and started loading
  their thumbnails. The shared virtualized list now mounts an initial batch of
  eight and retains a five-viewport window. Search and filtering keep their
  existing results and ranking. The results are recomputed only when a search
  input, locale or library visibility changes. The fixed glass header, back
  control, dock inset and artwork presentation continue to use shared components.
- Technique used one image view and replaced its source on every phase change.
  The current card now warms the sibling after the initial image loads, keeps
  both sources mounted for that pair, and switches visibility after the target
  loads. Android's default per-image fade is disabled for these phase views.
  Changing exercise or character resets the pair. The platform image cache
  continues to handle bundled sources. No catalog-wide preload, cache layer,
  image processing or changes to size, logo or artwork assets.
- Source audit covered Workout, Home, Progress/MuscleProgress, MuscleMap,
  AppScrollView, BrandHeader, BackSwipe, AppPicker, WheelPickerSheet and global
  workout, theme and localization state. Progress already retains its panes and
  BackSwipe already drives its gesture with worklets and observes Reduce Motion.
  The shared wheel already uses a local native implementation when available
  and a virtualized fallback. The measurements did not establish a separate
  code change for those paths. Workout persistence and timers are outside the
  changed paths.

## Before and after in Chromium

Linux headless Chromium, local production web exports, 844 px viewport height,
touch emulation and Reduce Motion. Before used `87c6c9b`; the eventual base
`0d176c2` adds documentation and version metadata only. Three fresh browser
contexts per width and build. Table shows medians. The timings include
Playwright action and assertion overhead. They do not measure device FPS,
input latency on a phone, or compositor frame times.

| Metric                                                             | 320 px before → after | 390 px before → after |
| ------------------------------------------------------------------ | --------------------: | --------------------: |
| Cold navigation to first usable dock, ms                           |         1,339 → 1,472 |         1,455 → 1,447 |
| Open library to first actionable row, ms                           |             221 → 109 |             250 → 110 |
| Mounted library rows after 450 ms                                  |               71 → 14 |               71 → 15 |
| Exercise image resource entries at library opening                 |               69 → 13 |               69 → 14 |
| Open bench press to image complete, ms                             |              89 → 105 |               89 → 88 |
| Action to image complete across eight phase switches, ms           |             64 → 53.5 |             54.5 → 49 |
| JS heap after GC with unfiltered library open, MiB                 |         25.01 → 22.51 |         24.99 → 22.58 |
| JS heap after GC following nine openings of the filtered card, MiB |         22.64 → 22.84 |         22.65 → 22.96 |

For the repeat-open sample, filter the library to Barbell Bench Press, open and
close its technique nine times, then use Chromium CDP
`HeapProfiler.collectGarbage` and `Runtime.getHeapUsage`. Use a consistent
search and card entry on both builds. Browser JS heap excludes WebP decode
buffers, native allocations and GPU surfaces. The two heap rows describe
different screen states. The largest consistent result is the reduction in work
on library entry. Cold launch and initial technique latency show no consistent
improvement. Dock action plus two RAF callbacks ranged from medians of
84–183 ms before and 75–183 ms after across the two widths, with mixed results
per tab.

## Additional browser scenarios

One paired 390 px run measured the following script-to-assertion durations in
milliseconds. This sample checks the paths and gives an indication of scale.
It does not establish a speedup or a regression.

| Scenario                                                  |    Before → after, ms |
| --------------------------------------------------------- | --------------------: |
| Library back button to Profile                            |               54 → 46 |
| Select female character, reopen library and load the card |             438 → 303 |
| Apply dark / light theme, then await two RAF callbacks    |     87 / 66 → 87 / 84 |
| Open language wheel                                       |             101 → 107 |
| Open Muscle Map and muscle discovery                      |             158 → 170 |
| Toggle chest / front deltoid highlights                   |     16 / 12 → 18 / 14 |
| Open and cancel weight / rep editors with wheels          | 378 / 467 → 421 / 363 |

At both widths a separate run scrolled the full library, verified female
artwork, returned through the back control, toggled two muscle highlights,
opened all three wheels, and preserved a decimal draft, a recorded set and its
rest deadline across tab changes. Exercise search and library layout passed in
English LTR and Urdu RTL. The broader localization browser suite passed
English at both widths and Urdu at 390 px. At 320 px its Urdu onboarding
calendar clips a weekday at the same step on both builds, before the
Exercise Library is opened. This existing onboarding issue remains tracked
separately from the P0.2 paths. Native swipe and picker gesture timings remain
part of the device checklist.

## Physical iPhone and Android checklist

Status for both platforms: **not tested**. Record agreed devices on 60 Hz,
OS, build type, commit SHA, refresh rate, power mode and any background
conditions. Compare the same data on both builds using native release-like
profiling. Use Instruments/Core Animation on iOS and Perfetto frame timelines
on Android. Report frame distribution and the percentage at or below 16.7 ms,
counts above budget and JS/UI stalls. Acceptance target is at least 95% within
16.7 ms. Report native process and graphics memory after warm-up and repeated
cycles; Chromium resource counts and JS heap do not establish a device pass.

1. Cold-start three times, then switch all dock tabs repeatedly with empty and
   populated history. Check that the header and dock stay in place.
2. Swipe back on nested pages from both approved edges. Test cancellation and
   completed gestures, Reduce Motion, LTR/RTL, restored scroll position and
   navigation with a keyboard or picker open.
3. Open the library, scroll to the final rows, search/filter and open a card.
   Return to the same place. Open and close ten distinct exercises, then repeat
   twice. Capture native memory before, during and after the cycles.
4. Within a card alternate START / FINISH, including rapid reversals, and the
   expanded viewer. Repeat with male and female artwork, light and dark themes
   and both normal and enlarged text. Look for stale phases, flashes or cropping.
5. Open Muscle Map and toggle several muscle targets. Capture interaction frame
   timing. Check model, masks and red highlighting.
6. Exercise the weight, rep and language wheels. Save a decimal draft, record a
   set, switch tabs and return while the rest timer runs. Check draft, completed
   set and deadline before and after. Repeat with the app offline.
