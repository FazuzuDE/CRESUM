# P0.4 timer recovery

## Scope and observed regressions

- The Workout screen derives rest from the saved deadline and refreshes from
  the clock on return to the foreground. The completion haptic is armed only
  when the open screen observes a countdown in the foreground. A deadline that
  already passed during backgrounding, tab navigation or restart does not
  replay a haptic on return. A countdown still running on return can complete
  with one foreground haptic. Skip, a changed deadline and screen unmount
  replace or disarm the old foreground countdown.
- A cardio interval can legitimately have an earlier wall-clock timestamp than
  the workout start when the device clock was moved backward during a session.
  The repository accepts that active snapshot so the workout remains
  recoverable. It still validates timer fields and rejects running intervals in
  completed history. Clock-based elapsed time stays capped by the cardio goal.
- Reopening a program cardio timer while its previous screen was saving could
  show the old countdown. Reads now wait for queued cardio writes before
  reopening the running timer or showing the measured duration in History.

There is no local OS notification scheduler in the inspected base. These
changes address the existing foreground haptic and persisted rest/cardio
state. They request no notification permission. Locked-screen delivery,
permission denial and cancellation of OS notifications require a scheduler
before they can be verified. Offline workout logging remains available.
System wall-clock corrections can change the displayed time. The one-second
resume target applies to controlled runs with a stable device clock.

## Physical iPhone and Android acceptance

Both devices remain untested. Use an internal iOS or Android build, record
build SHA, model, OS version and measured interval.

1. Start a 30-second rest. Lock for about 10 seconds, unlock and compare the
   display to an external clock. Repeat with the display locked past expiry.
   A future deadline keeps counting. An expired one reads complete without a
   catch-up haptic. Check one haptic when the timer finishes in the foreground.
2. During rest, switch tabs, force-close and reopen, then repeat after a device
   reboot. Check the same workout ID, completed sets and remaining time.
   Skip, change the deadline and finish in separate runs. Confirm no old
   haptic and no restored active workout after Finish.
3. Start manual cardio and program cardio explicitly. Repeat the background,
   force-close and reboot cases before and after the goal. Check paused time
   excludes background time and running time is capped at the goal. Confirm
   manual cardio still pauses when switching exercises.
4. Move the wall clock backward before starting manual cardio. Restart and
   confirm the active workout still opens. Move the clock forward and check
   workout and history state. Run the ordinary timing cases offline as well.
5. In any future build with OS scheduling, add lock-screen delivery,
   permission denial, silence mode, skip, finish, reset, rescheduling and
   startup reconciliation checks. Count duplicate or stale deliveries.
